## Bugs bloqueantes

### [BUG-01] Data leak: docente personal ve secciones institucionales
- **Suite:** B.4
- **Reproducción:**
  1. Registrar cuenta personal (`POST /api/auth/registro-personal/`)
  2. `GET /api/usuarios/secciones/` con el token recién obtenido
- **Esperado vs Actual:** Lista vacía → devuelve 13 secciones institucionales (con tutores, docentes asignados, etc.)
- **Impacto:** Cualquier docente que cree cuenta personal en la sub-app ve toda la estructura de la I.E. Multi-tenancy roto en `SeccionViewSet.get_queryset()` — no filtra por `modo_cuenta` ni por `owner`.
- **Archivo:** `backend/apps/usuarios/views.py` — `SeccionViewSet` sin filtro de tenant.

### [BUG-02] HTTP 500 en aceptar-invitacion (`select_for_update` sin `transaction.atomic`)
- **Suite:** C.3
- **Reproducción:**
  1. Director crea invitación (`POST /api/auth/invitar-docente/`)
  2. Docente personal acepta (`POST /api/auth/aceptar-invitacion/ {token: ...}`)
- **Esperado vs Actual:** HTTP 200 con mensaje de integración → HTTP 500
- **Error exacto:** `django.db.transaction.TransactionManagementError: select_for_update cannot be used outside of a transaction`
- **Archivo:** `backend/apps/usuarios/views_personal.py:288` — falta decorar la view con `@transaction.atomic` o envolver el bloque en `with transaction.atomic()`.
- **Impacto:** Flujo de integración docente personal→institucional completamente roto.

### [BUG-03] SIAGIE preview y rellenar fallan por campo `asignacion` removido del modelo
- **Suite:** D.4, D.5
- **Reproducción:**
  1. Analizar template (`POST /api/notas/siagie/analizar/`) — OK
  2. Preview (`POST /api/notas/siagie/preview/`) con el archivo + `seccion_id` + `bimestre`
- **Esperado vs Actual:** HTTP 200 con conteos → HTTP 400 con error interno
- **Error exacto:** `Cannot resolve keyword 'asignacion' into field. Choices are: actualizado_en, anio_lectivo, area, bimestre, calificacion, ...`
- **Impacto:** Toda la Suite SIAGIE (pasos 2 y 3 del flujo de 3 pasos) bloqueada. Solo funciona `analizar`.
- **Causa probable:** La función `_notas_por_dni` en `views.py` filtra por `asignacion__seccion_id` o similar, pero el modelo `NotaBimestre` ya no tiene ese campo (fue renombrado o removido en alguna migración).

## Bugs menores

### [BUG-04] Anti-bruteforce (django-axes) instalado pero no funciona en la práctica
- **Suite:** A.6
- **Reproducción:** 6+ intentos fallidos contra cualquier usuario desde la misma IP → sigue retornando HTTP 401 (no 403)
- **Esperado vs Actual:** HTTP 403 tras el 5° intento → HTTP 401 indefinidamente
- **Causa:** El `login` view en `views.py:40` usa `authenticate()` directamente con `AxesStandaloneBackend`, pero **no llama a `axes.helpers.get_lockout_response()`** ni verifica `axes.helpers.is_already_locked()` antes de intentar autenticar. Axes registra los intentos (confirmado: se acumulan en `AccessAttempt`) pero el bloqueo no se aplica porque el view customizado no lo consulta.
- **Nota adicional:** El bloqueo de axes también afecta todos los logins desde la IP compartida del nginx container (172.28.0.5), causando falsos positivos que bloquean usuarios legítimos desde el mismo origen.

### [BUG-05] `SeccionViewSet` deniega creación a docentes personales (gap multi-tenancy)
- **Suite:** B.2
- **Reproducción:** `POST /api/usuarios/secciones/` con token de docente personal
- **Esperado vs Actual:** HTTP 201 + sección propia → HTTP 403 "Solo el equipo directivo puede gestionar secciones"
- **Causa:** El check `_check_staff()` no distingue entre modo institucional y personal. En modo personal, el docente debería poder crear sus propias secciones (aisladas por `owner`).
- **Impacto:** El flujo multi-tenancy personal está incompleto — un docente personal no puede crear la estructura básica para usar la sub-app.

### [BUG-06] `SiagieRellenoLog` registra acción `rellenar` aunque la operación falle
- **Suite:** D.6
- **Evidencia:** La tabla tiene un registro con `accion=rellenar` a pesar de que D5 retornó HTTP 400.
- **Causa:** El log se crea antes de verificar el éxito de la operación (en `siagie_rellenar`, el `SiagieRellenoLog.objects.create()` está antes del return de error).
- **Impacto:** Auditoría contaminada con operaciones fallidas marcadas como ejecutadas.

### [BUG-07] Cache SIAGIE almacena mapeo parcial para template secundaria (4/9 columnas)
- **Suite:** D.7
- **Evidencia:**
  - `template_secundaria_5to.xlsx`: método=`cache`, 4 columnas detectadas (`codigo, dni, apellidos, sexo`) — faltan `orden` y las 4 competencias NL
  - `template_primaria_5to.xlsx`: método=`ia`, 11 columnas detectadas (incluyendo `nota_nl_*` y `conclusion_*`) — correcto
  - `template_inicial_5anios.xlsx`: método=`ia`, 9 columnas detectadas — correcto
- **Causa probable:** El template secundaria fue analizado por primera vez con heurística débil (ver SUG-04 del plan) y ese mapeo incorrecto quedó guardado en `SiagieMapeo`. Las ejecuciones siguientes retornan el cache sin re-analizar.
- **Fix sugerido:** Borrar el registro en `SiagieMapeo` para el hash `2c5047ba45e27ee6...` y re-analizar; corregir los patrones heurísticos según SUG-04.

## Observaciones adicionales

- **Health check `/api/health/` no existe**: El plan asume `GET /api/health/` → `{"status":"ok"}` pero la ruta devuelve 404. Hay un `/healthz` configurado en nginx que retorna `200 ok` (texto plano). Menor discrepancia entre plan y realidad.
- **Axes y nginx compartiendo IP**: El backend ve siempre `172.28.0.5` (nginx) como client IP. Axes bloquea por (username, ip), pero si se fija por ip sola, un lockout afectaría a todos los usuarios simultáneamente. Revisar `AXES_IPWARE_META_PRECEDENCE_ORDER` para que tome `X-Real-IP` o `X-Forwarded-For`.
- **Token JWT expira rápido durante pruebas**: Varios tests fallaron por token expirado entre el login y el uso. Confirmar que `ACCESS_TOKEN_LIFETIME` esté configurado para un tiempo razonable en producción.
